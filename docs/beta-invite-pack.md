# Beta Invite Pack

Use this when inviting the first five to ten external testers.

## Short Invite

Subject: Agora v0.1 beta: try the Acme client-launch workflow

Hi,

I am opening a small guided beta for Agora, an open source project-management workspace for client-facing teams that want no ads, no trackers, portable data, and auditable AI.

The beta goal is simple: can you understand and run the Acme client-launch workflow without me explaining every screen?

Start here:

- Demo URL: `<demo-url>`
- Acme story: `<generated-acme-link>`
- Feedback form: `<feedback-url>`
- Setup notes: `<release-notes-url>`

Please do not enter real customer data, private emails, secrets, service-role keys, payment credentials, or private file URLs. Use sample or anonymized project data only.

What I would love feedback on:

- Was the first useful action obvious?
- Did the client-delivery story feel real?
- Did export/recovery proof feel trustworthy?
- What blocked you from using this on a real project?
- Which screen felt too dense or unclear?

Thank you for kicking the tires.

## Tester Instructions

1. Open the demo URL.
2. Follow the Acme flow: command center, project backlog, client visibility, timeline, reports, data recovery.
3. Submit one feature request or bug through the Feature Request button.
4. If self-hosting, run the Quick Start and export a portable bundle.
5. Send the maintainer any screenshots only after checking for private data.

## What Not To Enter

- Real customer names, emails, files, contracts, or project details.
- API keys, service-role keys, AI provider keys, Stripe keys, SMTP secrets, or webhook secrets.
- Private repository URLs or private file links.
- Anything you would not be comfortable seeing in a public bug report.

## Follow-Up Triage

Every tester response should become one of:

- `P1`: blocks setup, demo completion, export, restore, auth, or core client workflow.
- `P2`: important before broad beta but not blocking guided testers.
- `P3`: useful later.
- `docs`: confusion that can be solved with copy, docs, or onboarding.
- `reject`: not aligned with Agora's open, portable, no-ads/no-trackers product promise.
